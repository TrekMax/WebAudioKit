# ADR-014：信号处理教学模型与运行时分离

- 状态：Accepted
- 日期：2026-08-13

## 背景

项目需要在顶部导航新增“信号处理图解”，从复数、欧拉公式和旋转相量逐步解释离散采样、DFT、FFT、窗函数和 STFT，并通过 Three.js 提供可操作的三维教学演示。现有 `Fft3DView` 是分析结果视图，它与 `StftPreviewResult`、dBFS 范围、播放头和分析参数绑定，不适合直接承载通用数学教学场景。

## 决策

- 新页面使用独立的纯数据教学目录和数学模型。复数、DFT、幅相谱、窗函数与有界 STFT 不依赖 React、DOM、Web Audio 或 Three.js。
- 同一份模型数据驱动参数读数、SVG/Canvas 二维投影和 Three.js 三维场景，避免降级视图与三维视图的数学结果漂移。
- 教学 DFT 使用未归一化的复数定义，并在单边幅度展示层明确应用缩放。FFT 只解释为高效计算 DFT 的算法族，不建立第二套数学频谱定义。
- 教学信号仅使用确定性生成的正弦、双音、扫频、脉冲和静音；页面不读取当前 PCM、不创建 AudioContext、不发送 Worker 消息、不写入项目状态。
- Three.js 演示通过 `React.lazy` 动态载入，只在用户打开可见的三维场景时创建渲染器。静止场景按需渲染；动画由用户显式播放并受 `prefers-reduced-motion` 约束。
- 三维场景不直接复用 `Fft3DView`。可抽取的共享能力只包含容器尺寸、WebGL2 能力判定、上下文丢失/恢复、按需帧调度和对称 `dispose()`。
- 首版提供旋转复数、DFT bin 累加和 STFT 形成三个场景。模型规模固定上限；实时循环不创建大对象、不扩容数组、不运行无界计算。
- WebGL2 不可用或上下文丢失时，保留同一模型生成的文字摘要和 SVG/Canvas 二维投影。三维演示不是理解知识链的唯一途径。
- 页面、演示和标签都提供语义化名称、当前参数文本与键盘操作。纯颜色不承担唯一的状态表达。
- `AppPage` 显式加入 `signal-knowledge`，页面分支不使用“其他全部默认进入知识图谱”的隐式 `else`。实时频谱可见性测试必须证明两个知识页都不调度 FFT。

## 结果

优点：

- 数学模型可以用 DC、静音、bin 对齐正弦、脉冲和共轭对称做确定性测试。
- 二维与三维演示共享参数与数据，WebGL 降级不会改变教学结论。
- 知识页不干扰用户的播放、分析、滤波和导出链路。
- Three.js 保持懒加载，不增加首屏必需代码。

代价与限制：

- 需要同时维护 SVG/Canvas 和 Three.js 渲染器，必须依赖共享模型和读数测试控制漂移。
- 教学 DFT/STFT 只处理小型确定性数据，不替代 Worker 中的权威全文件分析。
- 交互式教学场景增加了可访问性、降级和 GPU 资源释放的测试成本。
