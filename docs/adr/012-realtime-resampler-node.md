# ADR-012：采样率转换只模拟非破坏式监听效果

- 状态：Accepted
- 日期：2026-08-07
- 更新：2026-08-08

## 背景

节点编译器需要增加可配置上/下采样的采样器节点，同时项目仍要求源 PCM 不可变、播放不中断、内存有界。Web Audio 图中的所有中间节点最终必须按 AudioContext 的固定采样率输出，不能由单个节点真正改变声卡或图的采样率。

## 决策

- 采样器属于湿声监听分支，不进入源 PCM、权威 FFT/STFT 或导出管线。
- 目标采样率范围为 3–192 kHz。低于 AudioContext 采样率时，AudioWorklet 使用有界一阶低通预滤波，再按相位累加器抽取；声明式配置保存 `hold | linear` 算法，默认 `hold` 保留既有听感与配置兼容性。
- `hold` 对抽取值执行零阶保持，突出低采样率的阶梯质感；`linear` 保存前后两个抽取值并在下一个模拟采样间隔内分段线性重建，因此引入最多一个目标采样间隔的因果延迟，在最低 3 kHz 配置下约为 0.33 ms。
- 目标采样率不低于 AudioContext 采样率时保持透明；AudioBufferSourceNode 到 AudioContext 的原生转换已完成必要插值，但不宣称产生超过上下文 Nyquist 的新频率信息。
- 算法通过 `processorOptions` 进入 Worklet，切换算法时在控制线程替换当前监听路由；目标采样率继续使用 k-rate AudioParam 原位更新。
- Worklet 构造阶段预分配最多 32 声道的滤波、相位、前一值与当前保持值状态。实时 `process()` 不分配对象或 TypedArray，不执行日志、I/O、Promise、动态导入或无界循环。
- AudioWorklet 不可用或模块加载失败时使用 GainNode 透明旁路。模块就绪后在控制线程原子替换湿声链并释放旧节点。
- 频谱预览为 `hold` 叠加下采样预滤波的幅频响应；`linear` 额外叠加一阶保持的近似 `sinc²` 响应。它是监听预测，不替代效果后 PCM 的权威 STFT。

## 结果

优点：

- 可在不中断播放和不复制整段 PCM 的前提下比较采样率降低的听感。
- 可在颗粒感更强的保持模式与更平滑的线性模式间切换，并保留相同的抗混叠基线。
- 实时线程的工作与声道数、render quantum 长度成固定上限关系，符合实时安全约束。
- 不支持 AudioWorklet 的浏览器仍能播放，且不会静音或破坏源数据。

限制：

- 这是实时监听效果，不是高质量离线重采样器，也不会改变 WAV 导出的采样率。
- 一阶抗混叠与两种重建模式侧重实时成本与可预期性，不等同于多相 FIR/SRC。
- 线性模式存在不超过一个目标采样间隔的因果延迟；高质量 FIR 及其 A/B 延迟补偿属于后续独立决策。
- 超过 32 声道时额外声道透明直通；常规浏览器输出布局不会触及该上限。
